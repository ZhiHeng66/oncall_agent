# 二次开发 06：Human-in-the-loop

## 何时必须人工审批

- 重启、扩缩容、发布和回滚。
- 修改配置、数据库或网络策略。
- 删除数据或资源。
- 对外发送通知或创建工单。
- 成本或影响范围超过阈值。

## 工作流

```text
Executor 准备工具调用
→ Policy Engine 评估风险
→ 低风险只读：直接执行
→ 高风险：写入 pending action + Graph interrupt
→ 用户查看参数/证据/影响并批准或拒绝
→ 从持久 Checkpoint 恢复
→ 再次校验权限和时效
→ 使用幂等键执行
```

审批记录应包含 approver、时间、原始参数 hash、修改后参数、理由和执行结果。审批不能永久有效；恢复时如果环境已变化，应重新规划或重新审批。

## 安全原则

模型只能“建议”高风险操作，服务端 Policy 决定是否需要审批。不能通过 Prompt 让模型自行判断自己是否有权限。恢复执行前防止重复提交，并为可逆操作设计回滚。
